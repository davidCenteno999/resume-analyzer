# Analysis contract before dashboard work

`POST /resume/upload-resume` currently reads a PDF, extracts text with PyPDF2, sends it to the configured LLM, normalizes nullable degree and experience values for matching, and returns `{filename, extracted_data, compare_result}`. The LLM schema contains nullable `name`, `email`, `phone`; `skills: string[]`; `experience: [{title, company, years, description}]`; and `education: [{degree, institution, years}]`. The form sends `required_skills`, `degree_requirements`, and `experience_requirements: [{title, years}]`, all required and nonempty.

`compare_result` contains `skill_match`, `percentage_skill_match`, `degree_match` (boolean), `experience_match`, and `percentage_experience_match`. Originally, skill matching used case-sensitive string membership, which missed equivalent capitalization and counted duplicate requirements. Current skill and tool matching uses NFKC Unicode normalization, `casefold()`, whitespace collapsing, exact equality, and normalized deduplication. The first original requirement label is retained in matched/missing lists; `evaluated_skills` and `evaluated_tools` expose the unique comparison set. The original submitted arrays and extraction are stored unchanged. Degree matching still checks whether any required degree is a substring of the **first** extracted degree. Experience matching still counts qualifying title/year pairs. The original response had no matched or missing lists, separate tools, overall score, or persisted history. Empty category requirements were rejected by the schema. Overall score remains `null` because no established cross-category calculation exists. All dashboard dates and bucket labels use UTC; weeks start Monday.
